VERCEL DEPLOYMENT GUIDE — READ BEFORE PUSHING

PACKAGE STATUS
The source files have been gathered into a clean separate folder. The original project has not been modified. This package includes a Vercel-detectable `server.ts` entrypoint that starts the existing Node HTTP application in `server.js`; the copied server defaults to binding on all interfaces when no HOST is set. Vercel announced automatic Node server detection for root `server.ts` and `src/server.ts` on June 23, 2026.

GIT SOURCE UPLOAD
1. Use this package folder as the repository root when creating a GitHub repository (for example, with GitHub Desktop).
2. Check that `.env`, `data/`, user uploads, `node_modules/`, and service-account files are not staged.
3. Push the source to the Git repository.
4. Import that repository into Vercel to create a Preview deployment first. Git pushes to connected repositories can trigger deployments.

NEVER COMMIT
- `.env`
- Firebase service-account JSON or private keys
- `data/db.json` or backups
- private upload folders
- `node_modules/`
The included `.gitignore` excludes these paths. Review the staged file list before the first push.

VERCEL ENVIRONMENT VARIABLES
Set these in the Vercel project settings, not in Git:
- Production uses `DATA_STORE=firestore` and `FIREBASE_PROJECT_ID=kuldeep-malviya-portfolio`.
- Preview must use a dedicated staging Firebase project ID and its own `FIREBASE_SERVICE_ACCOUNT_JSON`; never copy Production credentials to Preview.
- Add `SITE_URL` to match the assigned Preview/Production origin and `COOKIE_SECURE=1` for HTTPS.
- For initial staging admin setup only, set a strong random `ADMIN_BOOTSTRAP_TOKEN` in Preview; remove it after creating the staging admin and configuring MFA.
Vercel supplies `PORT`; do not copy the local `.env` values for HOST/PORT. Keep `ADMIN_BOOTSTRAP_TOKEN` unset unless a fresh admin bootstrap/reset is specifically required. The existing database currently reports an admin configured.

PRODUCTION BLOCKER: UPLOADED MEDIA
CMS media uses short-lived signed uploads to Vercel Blob; it does not write persistent files to the Vercel Function filesystem. Connect one public Blob store to Production and a separate store to Preview. The app recognizes `BLOB_READ_WRITE_TOKEN` only in Production and requires `BLOB_PREVIEW_READ_WRITE_TOKEN` in Preview. Public media URLs can be viewed by anyone who has the link. Upload limits are 20 MB per image, 100 MB per video, with a 900 MB application safety cap; verify plan usage and the current no-cost allowance before launch. Existing images in `assets/` remain packaged as code assets.

FIREBASE ACCESS
- Firestore rules and indexes are included in `firebase/` and `firebase.json`.
- Git/Vercel import does not itself publish Firebase rules. Confirm the deployed Firestore rules remain deny-by-default for direct browser access.
- The app uses the Firebase Admin SDK on its server side. The browser should continue to use the portfolio's own API.

PLAN NOTE
Vercel's current terms restrict Hobby use to personal/non-commercial projects. This portfolio advertises professional services, so confirm the intended usage against Vercel's current plan terms before production deployment. Use an eligible plan if the site is commercial.

DEPLOYMENT ORDER
1. Push this clean package to Git after checking the staged files.
2. Configure Vercel secrets/environment variables.
3. Create a Preview deployment and inspect homepage, projects, services, admin login, CMS reads/writes, contact flow, and media behavior.
4. Set up durable media storage before relying on uploads.
5. Configure final domain/SITE_URL and secure cookies, then deploy Production only after the Preview is acceptable.
